# Архитектура решения: детектор, шкала событий, правила, каталог норм

Решение принято 17.10.2026 по итогам двух вещей. Первая — покадровый разбор всех 40 роликов ([docs/video_analysis](video_analysis/README.md)). Вторая — замеры моделей на CPU и исследование вариантов: детекторы, слой событий, устойчивость к ракурсу, локальные VLM.

## 1. Решение в одном абзаце

Сервис — **один Docker-образ на CPU**. Конвейер устроен так:

1. **ffmpeg** читает видео.
2. **YOLOX-s в ONNX Runtime** (Apache-2.0) находит людей и предметы.
3. **ByteTrack** из пакета `trackers` (Apache-2.0) склеивает людей в треки.
4. Дешёвые **мониторы состояний** по зонам, привязанным к найденным объектам: экран, сейф, дверь, стол, машинка, детектор банкнот.
5. **Шкала событий** (флюенты с гистерезисом и мгновенные события).
6. **Правила-автоматы**, сгруппированные по четырём моментам проверки: уход кассира, вход человека, сеанс обслуживания, рабочее место.
7. **Ответ**: таймкод, кадры, текст по шаблону и ссылка на норму из сверенного вручную каталога `rules.json`.

Обучения нейросетей в первой версии нет. Во второй версии добавляется **дообученный «доменный» детектор** — деньги, сумка инкассации, кассовая книга, печать, ключ в замке, сейф открыт, экран включён, дверь открыта. Он даёт устойчивость к новому ракурсу. Визуально-языковая модель на вердикт не влияет (раздел 9).

## 3. Что показали данные (кратко)

Подробно — в [video_analysis/README.md](video_analysis/README.md).

- **22 события, 17 типов.** Все они — пропущенный шаг в одном из четырёх моментов:
  - уход: деньги, сумка, документы, сейф, ключ, экран — 9 событий;
  - вход: дверь, посторонний, деньги прошлого клиента — 7;
  - сеанс: инкассатор, пересчёт при клиенте, пересчёт перед сейфом, детектор, документ — 6;
  - рабочее место: вещи, напиток — 2.
- **Шесть ракурсов камеры уже в обучающих данных.** Это позволяет честно проверять перенос на новый угол («оставь одну камеру»).
- **Метка стоит на действии человека:** отошёл к двери, вошёл, сел работать, взял стакан. Наш момент совпадает с меткой с точностью ≤ 1 с в 20 случаях из 22.
- **YOLOX на COCO уже видит:** людей, ноутбук (99–100%), стакан, сумку, «предмет на столе» (пачка денег как `cell phone`/`book`).
- **YOLOX не видит:** сейф (иногда `tv`), ключ, удостоверение, детектор банкнот, куртку. Не различает «открыт / закрыт» и «включён / заблокирован».
- **Главная ловушка — отражения в стекле.** Они дают «второго человека» в 13–89% кадров.

## 4. Какие варианты рассматривали

| Вариант | Почему нет (или почему да) |
|---|---|
| Распознавание действий целиком (обучение на видео: VideoMAE, X3D, SlowFast) | 40 роликов, одна метка на ролик, типов нет. Модель выучит «какая это камера», а не «что сделал кассир»; на новом ракурсе развалится. Многие веса CC-BY-NC |
| VLM смотрит кадры и решает | Замер: Qwen3-VL-2B — 10–11 с на полный кадр на 4 vCPU, и то на один вопрос. На смысловых вопросах ошибается («рабочий экран» → «экран блокировки»), а без кропа не видит мелочь сверху (ключ 6×4 px, экран 25×20 px). Объяснимость и таймкод хуже |
| Зоны в пикселях, нарисованные вручную | Жюри шлёт видео через API и ничего не калибрует; новый угол ломает всё |
| Классификатор по признакам ролика | Выучит ложные подсказки: длительность (ролики с нарушением короче), камеру K3, где 2 из 3 роликов — нарушения |
| **Детектор + треки + шкала событий + правила (v1)** | **Да.** Объяснимо: у каждой тревоги есть рамка, момент и пункт нормы. Не нужно обучение. Новый тип — новое правило. Так же устроены системы против мошенничества на кассах (StopLift, IBM): примитивы по зонам, потом проверка порядка шагов |
| **Дообученный доменный детектор (v2)** | **Да, вторым шагом.** Закрывает то, чего нет в COCO (сейф открыт, ключ, деньги, удостоверение), и переносится на новый угол лучше, чем пиксельные пороги. Разметка дешёвая: статичные объекты размечаются одной рамкой на камеру, состояния — интервалами из нашей проверенной разметки |

## 5. Конвейер

```
.mov ─► [0] ffprobe/ffmpeg: поворот, частота, длительность; не видео → 415
          │
          ▼
     [1] Сцена (один раз): медиана кадров без людей
         YOLOX-s 960×544 / 1280×704 → ноутбук, машинка, стол, сейф(tv), стул
         зона двери: где рождаются и умирают треки, вошедшие в комнату
         масштаб: рост кассира в пикселях → все пороги в «ростах», а не в px
          │
          ▼
     [2] Люди (4–5 к/с): YOLOX-s 640×352 → ByteTrack → сшивка фрагментов
         фильтр отражений: высота ≥ 0,5 роста кассира, ноги на полу,
         трек вошёл через дверь или был в комнате с начала
         роли: кассир = дольше всех у рабочего места; клиент = вошёл и сел
         напротив; инкассатор = вошёл с сумкой; посторонний = на стороне кассира
          │
          ▼
     [3] Мониторы состояний (дёшево, на каждом кадре):
         экран (HSV в боксе laptop; ночной режим V ≥ 240),
         сейф и дверь (разница с эталоном «закрыто», когда никто не заслоняет),
         стол (классы YOLOX 960×544 раз в 1 с + двойной фон),
         машинка и детектор банкнот (движение в зоне), свет (скачок яркости)
          │
          ▼
     [4] Шкала событий
         флюенты с гистерезисом: cashier_at_desk, cashier_in_room, door_open,
         safe_open, screen_unlocked, item_on_desk, client_seated, machine_active…
         события: stand_up, leave_desk, exit_room, enter_room, sit_down,
         object_placed/removed, light_off
          │
          ▼
     [5] Правила-автоматы по 4 моментам:
         УХОД   → что открыто: деньги/сумка/документы/сейф/ключ/экран (T01–T06)
         ВХОД   → дверь закрыта? кто вошёл? что на столе? (T07–T09)
         СЕАНС  → порядок шагов: документ→деньги, пересчёт при клиенте,
                  детектор, инкассатор до конца проверки (T10–T14)
         МЕСТО  → вещи, напитки при деньгах (T15–T16)
         общий запасной: «ценность без присмотра», «лишний человек» → T99
          │
          ▼
     [6] Решение: уверенность события → вердикт (порог T1 по CV);
         склейка событий одного типа в пределах 10 с; несколько типов — несколько событий
          │
          ▼
     [7] Ответ: таймкод = опорное действие + сдвиг, выученный на разметке;
         кадры [t, t−1, t+1] точной перемоткой ffmpeg;
         описание по шаблону из измеренных фактов;
         «Основание:» только из rules.json; lint запрещённых слов
```

### Ключевые решения внутри конвейера

- **Два прохода по стоимости.** Люди крупные, им хватает 640×352. Мелкое (экран, пачка денег) смотрим в 960×544 раз в секунду и в 1280×704 в ключевые моменты (уход, вход).
- **Зоны привязаны к найденным объектам и людям, а не к пикселям.** Экран — верхняя часть бокса `laptop`. Стол — область под руками сидящего кассира и вокруг ноутбука и машинки. Дверь — по рождению треков. Сейф — `tv`/OWLv2/доменный детектор, иначе «шкаф у стены, к которому кассир подходит без клиента».
- **Выход из комнаты — это проход через зону двери, а не потеря трека.** Трек ещё 3–5 с виден за стеклом.
- **Состояние до выключения света сохраняется.** Если в темноте экран светится — это сильный признак T06 (Х-11).
- **Шкала событий по модели Event Calculus.** Флюенты с началом и концом, инерцией, минимальной длительностью и гистерезисом. Ложная детекция на одном кадре не рождает нарушение.

## 7. Скорость (замерено здесь, Intel Xeon 2,1 ГГц, ONNX Runtime 1.29)

| Модель и вход | 1 поток | 2 потока | 4 потока |
|---|---|---|---|
| YOLOX-tiny 416×224 | — | 21 мс | 17 мс |
| YOLOX-tiny 640×352 | — | 50 мс | 28 мс |
| YOLOX-s 640×640 (квадрат из релиза) | 194 мс | 103 мс | 65 мс |
| **YOLOX-s 640×352 (портрет)** | — | **67 мс** | **38 мс** |
| YOLOX-s 960×544 | — | 139 мс | 85 мс |
| YOLOX-s 1280×704 | — | 265 мс | 151 мс |
| YOLOX-m 640×640 | 493 мс | 287 мс | 177 мс |
| ffmpeg: декодирование 142,5 с в 5 к/с | — | ≈ 7 с | — |

**Бюджет на худший ролик (145 с) на 2 vCPU:**

| Шаг | Время |
|---|---|
| декодирование | 7 с |
| люди: YOLOX-s 640×352 × 4 к/с = 580 кадров | 39 с |
| стол: YOLOX-s 960×544 × 1 к/с | 20 с |
| ключевые моменты: 1280×704 × ~20 | 5 с |
| мониторы | < 5 с |
| **итого** | **≈ 75 с** |

На 4 vCPU — около 45 с. Медианный ролик (23 с) обрабатывается за 10–15 с.

**Опасность — burstable-машины.** Azure B-серия без накопленных кредитов работает на 20–30% мощности, то есть в 3–5 раз медленнее. Два ролика одновременно уже не уложатся в 240 с. Поэтому берём VM без кредитов (D2as_v5 / D4as_v5) или B4ms с запасом кредитов. Плюс режимы по оставшемуся времени: при нехватке — 2 к/с и YOLOX-tiny.

Справочно: прогон «на максимум» (YOLOX-s 960×544 на 5 к/с по всем кадрам, 4 потока, CPU делят агенты) обработал 1300 с видео примерно за 1330 с.

## 8. Устойчивость к новому ракурсу (10 баллов плюс часть критериев 1–3)

- **Переносится:**
  - есть ли предмет;
  - сколько людей на стороне кассира;
  - порядок событий: «ушла → осталось», «вошёл → сел»;
  - расстояния в ростах человека;
  - состояние экрана по боксу `laptop`;
  - «открыто / закрыто» относительно эталона того же видео.
- **Не переносится:** зоны и пороги в пикселях, «сейф справа», цвет одежды, глобальные эмбеддинги кадра.
- **Проверка:** кросс-валидация «оставь одну камеру» (K1 / K2 / K3 / K4+K5 / K6). Плюс синтетические искажения (перспектива, поворот, кадрирование) и 6–10 своих роликов под другим углом (FAQ 7 разрешает).
- **Доменный детектор (v2)** учим с аугментациями перспективы, поворота и масштаба. Разметка:
  - статичные объекты (сейф, машинка, детектор, дверь, ноутбук) — одна рамка на камеру переносится на все кадры;
  - состояния (сейф открыт, дверь открыта, экран включён, ключ в замке) — по интервалам из [`data/labels_verified.csv`](../data/labels_verified.csv) и [S2.md](video_analysis/S2.md);
  - вручную — только подвижное: деньги, сумки, книга, печати, стакан, удостоверение. Это около 150–300 кадров.

## 9. Визуально-языковая модель (VLM)

**Вывод: в v1 VLM нет.** В v2 она появляется как необязательный проверяющий за флагом, отдельной фазой после детектора, с жёстким лимитом 60 с. Она никогда не отменяет сильное срабатывание правила и никогда не пишет текст или ссылку на норму. Её выход — только поля-перечисления (enum) в JSON.

**Замер на 4 vCPU** (Xeon 2,1 ГГц, llama.cpp b11706, llama-server, temp 0, `response_format: json_schema`, кроп с апскейлом до 448 px):

| Модель (лицензия) | Кроп 448 px | Полный кадр | Пик памяти | Микротест «видимые признаки» |
|---|---|---|---|---|
| **Qwen3-VL-2B-Instruct Q4 + mmproj F16** (Apache-2.0) | 3,6–6,5 с; повторный вопрос по тому же кропу — 1,3 с (кэш) | 10–11 с | 4,2–4,6 ГБ | 12/12 |
| Qwen3.5-0.8B Q4_K_M, `--reasoning off` (Apache-2.0) | 1,7–2,9 с | 3,8 с | 1,8–2,1 ГБ | 10/12 |
| Qwen3.5-2B Q4_K_M (Apache-2.0) | 3,6–6,5 с | 10 с | 3,7–4,0 ГБ | 10/12 |
| Gemma 4 E2B (Apache-2.0) | 3,5–5 с | 6,4–7,5 с | 4,9–5,9 ГБ | 9/12, не увидела сумку на столе |
| SmolVLM-500M (Apache-2.0) | 2,3–3,3 с | 3,5 с | 1,5 ГБ | 5/12, отвечает «да» на всё |

- **На 2 vCPU всё в 1,8–1,9 раза медленнее.** Если детектор занимает ядра, VLM проседает в десятки раз — поэтому только отдельной фазой.
- **Вопросы — только про видимые признаки** («экран тёмный?», «видна таблица?», «дверца сейфа открыта?»), а не про смысл («заблокирован ли компьютер»). На смысловой вопрос все модели ошиблись.
- **Проверка полярности:** спросить «открыт?» и «закрыт?». Противоречие или `unsure` — воздержание.
- **Если включаем, то Qwen3-VL-2B** на 4 vCPU (не больше 8 моментов на видео) или Qwen3.5-0.8B на 2 vCPU (не больше 4).
- **Где польза:** подтвердить кандидата средней уверенности — ключ в замке, «на столе деньги или документы», «в руках удостоверение».
- **Упаковка:** `llama-server` (бинарь 18 МБ или образ `ghcr.io/ggml-org/llama.cpp:server`) с локальными GGUF, без `-hf`, работает офлайн.

## 10. Сервис

- **API — ровно §10:**
  - `POST /api/v1/analyze` (поле `file`) отвечает `200 {"job_id","status":"processing"}`;
  - `GET /api/v1/jobs/{id}` — статусы `processing`/`done`/`failed`, схема без лишних ключей;
  - `X-API-Key` проверяется до приёма тела;
  - `image_base64` — «сырой» base64 JPEG (`/9j/…`);
  - 1–3 кадра, первый ровно в таймкоде.
- **Очередь внутри процесса.** Один uvicorn, SQLite, K рабочих потоков (1 на 2 vCPU, 2 на 4 vCPU). **Сторож дедлайна:** на 240 с задача отдаёт `done` с лучшим частичным результатом. Режимы по оставшемуся времени. Задачи жюри идут первыми. Кэш по sha256 — только для полного режима. Видео удаляется после обработки.
- **Интерфейс** — одна статическая HTML-страница с того же адреса:
  - загрузка и прогресс;
  - баннер с формулировками ТЗ;
  - карточки нарушений: тип, кликабельный таймкод, кадры, текст, карточка нормы;
  - шкала событий поверх локального превью видео;
  - «Скачать JSON».
- **Образ:**
  - `python:3.12-slim` + ffmpeg + onnxruntime;
  - веса в `/models`, `HF_HUB_OFFLINE=1`;
  - проверка `docker run --network none`;
  - amd64 собирается в CI (GitHub Actions → GHCR).
- **Хостинг.** VM без CPU-кредитов, адрес через Caddy с HTTPS. Горячий резерв — MacBook и ngrok.
- **Черновики кода** из `research_notes/…/service_architecture_and_deployment.md` содержат баги, их нельзя копировать без правок:
  - inline-комментарий в `COPY`;
  - таймкод вне длительности ролика;
  - нет сторожа дедлайна;
  - `numpy.float32` в JSON;
  - кэш деградированных результатов.
