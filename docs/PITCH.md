# Питч на 5 минут + 2 минуты вопросов

Формат свободный (слайды, сайт или живой показ). Лучший вариант: живой показ интерфейса с заранее загруженным роликом + 3–4 слайда-подложки. Ниже сценарий с таймингом.

## 0:00–0:40 — Проблема и ответ одной фразой
«Кассир ушла, а деньги остались на столе. На записи это 5 секунд, а в банке — часы просмотра. КассаКонтроль смотрит видео за вас: находит момент, показывает кадр и пункт правил НБРК, а решение оставляет человеку».

Ключевой принцип: ассистент, а не судья. Каждая находка — «может противоречить п. 20», а не «нарушил».

## 0:40–2:30 — Живой показ (заранее открыть результат ролика с нарушением)
1. Список проверок: загружаем ролик → видно этапы анализа (кадры, люди и предметы, правила, заключение).
2. Результат: слева кадр с рамками и увеличенный фрагмент, кадры до/во время/после, «что заметила система» по секундам; внизу шкала всего видео с меткой события.
3. Справа карточка: что видно → норма дословно со ссылкой на adilet → почему это может быть нарушением → чего по видео не видно → что проверить. Кнопки «Подтвердить / Не нарушение / Доп. проверка».
4. Вкладка «Категории»: 7 категорий, по каждой результат; честное «не проверялось» там, где признака нет.
5. «Заключение PDF»: документ как акт аудита — для службы контроля и архива.
6. «Ответ API»: тот же результат в формате ТЗ; жюри проверяет автоматически.

## 2:30–3:30 — Как устроено (один слайд)
- Только локально: YOLOX-s (Apache-2.0) + ByteTrack → люди, предметы, треки; никаких внешних ИИ, лица не распознаются.
- Правила по четырём моментам: уход кассира, вход человека, обслуживание, рабочее место. Пороги в долях роста человека, не в пикселях → работает при другом ракурсе.
- Каталог норм сверен вручную по adilet.zan.kz; модель ссылки не придумывает.
- Сторож времени 240 с, очередь, два обработчика; экономный режим при наплыве видео.

## 3:30–4:15 — Результат и честность (один слайд)
- 40 роликов: 11 из 21 нарушений найдено, 0 ложных тревог на 19 чистых, тип совпал у всех, время ±0,6 с.
- Чего не умеем и почему: сейф, ключ, дверь, пересчёт — нужен доменный детектор; это второй шаг.
- Почему 0 ложных тревог важнее: банк сказал, что ложные сигналы перестают читать.

## 4:15–5:00 — Что дальше для ForteBank
- Доменный детектор на 300–800 размеченных кадрах: сейф открыт, ключ, деньги, удостоверение → +6 типов.
- Подключение к видеоархиву банка и ежедневный отчёт по отделениям.
- Работает на обычном сервере без GPU — внедряется в контур банка без закупки железа.

## Вероятные вопросы
- **Почему не обучали модель на 40 роликах?** Одна метка на ролик без типов; модель выучила бы камеру, а не поведение. Правила объяснимы и переносимы; доменный детектор — следующий шаг с нормальной разметкой.
- **Другой ракурс?** Зоны от предметов (ноутбук, стол) и людей, пороги в ростах; проверяли «оставь одну камеру» на шести ракурсах обучающих данных.
- **Что при сбое?** Никогда не отвечаем «нарушений нет» по таймауту: отдаём частичный результат с пометкой; `failed` только если файл не читается.
- **Ложные тревоги?** На чистых роликах 0; каждое правило требует сочетания условий (ушла И осталось; вошёл И на стороне кассира).
- **Персональные данные?** Лица не распознаются, видео удаляется после анализа, результат 24 часа, всё на своём сервере.
