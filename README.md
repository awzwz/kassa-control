# КассаКонтроль

Локальный ИИ-сервис для проверки кассовой дисциплины по видеозаписи с камеры над рабочим местом кассира.
DATATHON '26 (Nazarbayev University, Астана), кейс ForteBank.

- Интерфейс: `https://<адрес>/ui/` (ключ тот же, что для API; можно передать `?key=…`)
- API: `POST /api/v1/analyze`, `GET /api/v1/jobs/{job_id}`, заголовок `X-API-Key` — формат ответа ровно по §10 кейса
- Описание API для жюри: `/ui/api.html`, OpenAPI: `/api/docs`, состояние: `/health`

## Что умеет

Четыре момента проверки и 9 типов нарушений (из 17 в каталоге `app/rules/rules.json`):

| Момент | Типы | Признак |
|---|---|---|
| Уход кассира | наличные / сумка инкассации / документы оставлены без присмотра; экран не заблокирован | кассир встал и вышел, на столе остался предмет; экран светится (светлые голубоватые пиксели) |
| Вход человека | посторонний в зоне кассира; деньги предыдущего клиента при следующем | второй человек рядом с кассиром или у стола во время обслуживания; новый посетитель при предметах на столе |
| Обслуживание | инкассатор ушёл до проверки сумки | стоящий посетитель пробыл у стола меньше 12 с, кассир продолжает одна |
| Рабочее место | личные вещи; напиток при наличных | сумка появилась вместе с кассиром и лежит при работе; стакан на столе у сидящего кассира |

Не проверяются в этой версии (честно помечены «не проверялось»): сейф открыт, ключ в замке, дверь не закрыта, порядок пересчёта, предъявление документа, детектор банкнот.

Проверка на 40 обучающих роликах (`tools/eval_rules.py`): 11 из 21 нарушений найдено, 0 ложных тревог на 19 чистых роликах, тип совпал у всех найденных, медианное расхождение по времени 0,6 с.

## Как устроено

```
Caddy (HTTPS) → api (FastAPI) → очередь задач в SQLite → worker ×2
                                   ffmpeg 5 к/с → YOLOX-s (ONNX, CPU/GPU) → ByteTrack → сигналы → правила
                                   → описание из каталога норм → кадры-доказательства
```

- `app/main.py` — HTTP API и статический интерфейс (`app/static`)
- `app/store.py` — очередь и результаты (SQLite, WAL; задачи берутся атомарно)
- `app/worker.py` — обработчик со сторожем дедлайна: через 240 с отдаётся лучший частичный результат; `failed` только если файл не читается
- `app/pipeline/` — `detector.py` (YOLOX), `signals.py` (стол, кассир, уход, посетители), `rules.py` (правила), `describe.py` (тексты), `video.py` (ffmpeg)
- `app/rules/rules.json` — каталог: тип → документ, пункт, дословная цитата, ссылка на adilet.zan.kz, шаблоны описания
- Все модели открытые с лицензией для коммерческого использования: YOLOX (Apache-2.0), trackers/ByteTrack (Apache-2.0), supervision (MIT), ONNX Runtime (MIT), OpenCV (Apache-2.0). Шрифты Inter и Geist — SIL OFL.
- Внешние AI-сервисы не используются; лица не распознаются; видео удаляется после анализа, результат хранится 24 часа.

## Нормативные источники

- Правила № 231 — постановление Правления НБРК от 29.11.2019 № 231 (с изм. на 12.07.2026): https://adilet.zan.kz/rus/docs/V1900019680 — пп. 12, 16, 19, 20, 22, 24, 25, 31, 32, 75, 80
- Правила № 14 — постановление Правления НБРК от 24.02.2020 № 14: https://adilet.zan.kz/rus/docs/V2000020075 — пп. 8, 16
- Правила № 49 — постановление Правления НБРК от 04.04.2019 № 49: https://adilet.zan.kz/rus/docs/V1900018545

Каждое описание заканчивается строкой «Основание: …» с пунктом и ссылкой; формулировки осторожные («может противоречить»).

## Запуск

```bash
# разработка
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python tools/prepare_models.py                 # веса YOLOX в models/
export API_KEY=test DATA_DIR=./data
uvicorn app.main:app --port 8000               # терминал 1
python -m app.worker                           # терминал 2 (можно несколько)
python tools/jury_sim.py --key test --concurrency 3 video1.mov video2.mov

# сервер
cp .env.example .env                           # API_KEY, DOMAIN
docker compose up -d --build                   # или tools/deploy.sh <ip> с ноутбука
```

Для GPU: собрать образ с `--build-arg BASE=nvidia/cuda:12.4.1-cudnn-runtime-ubuntu22.04` и установить `onnxruntime-gpu`; код переключится на CUDA сам.

## Инструменты для настройки

- `tools/run_detections.py` — прогон детектора по роликам в JSON (делается один раз)
- `tools/run_monitors.py` — пиксельные сигналы (экран, яркость)
- `tools/analyze_signals.py`, `tools/eval_rules.py` — разбор сигналов и проверка правил по разметке `data/labels_verified.csv`

## Известные ограничения

- Признаки настроены на 40 роликах одной комнаты с шести ракурсов; на новом ракурсе работают правила, не зависящие от пикселей, но предметы меньше ~15 px могут не распознаваться.
- При одновременной загрузке многих длинных видео на 4 vCPU сервис переходит в экономный режим (4 к/с); точность по времени события при этом немного падает.
- Решения проверяющего (подтвердить / не нарушение / доп. проверка) хранятся в браузере, а не на сервере.
